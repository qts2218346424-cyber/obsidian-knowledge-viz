# Knowledge Viz 产品愿景与路线图

> 本文记录 Knowledge Viz 面向公开用户和移动端的产品方向，作为后续功能设计、技术拆分和版本规划的共同依据。

## 1. 产品愿景

Knowledge Viz 不只是一个 Obsidian 可视化工具，而是一个**低门槛、可持续使用的个人知识与学习工作台**：

- 用户不需要先学会 Markdown，就能开始写笔记。
- 知识整理、学习复习、AI 查询、写作和专注可以在同一个工作区完成。
- 桌面端保留本地知识库和本地 Agent 能力。
- 手机端提供随时查看、记录、复习和 AI 查询的体验。
- 用户可以选择本地优先、云端同步、平台 AI 或自己的 AI。

## 2. 目标用户

### 新手用户

特点：不了解 Markdown、知识库结构和复杂工具，希望打开就能用。

重点体验：

- 新手引导和示例知识库。
- 普通文本写作作为默认编辑方式。
- 一键整理、总结、提问和生成复习卡片。
- 少量核心入口，隐藏复杂设置。

### 学习与考研用户

重点体验：

- 知识点整理。
- 错题和闪卡复习。
- 学习计划、番茄钟和复习提醒。
- AI 讲解、出题、批改和阶段总结。

### 重度知识管理用户

重点体验：

- Markdown、高级编辑和知识图谱。
- 标签、链接、孤立笔记和重复内容分析。
- 自定义工作区、快捷键、Skill 和 Agent。
- 本地 Claude Code、Codex 和其他本地 Agent。

### 内容创作者

重点体验：

- 漂亮的知识卡片和可视化页面。
- 主题、背景、组件和布局自定义。
- 将学习过程、知识图谱和复习成果整理成可分享内容。
- 后续支持公开页面、分享链接和产品演示模式。

## 3. 核心产品模块

### 3.1 知识库

- 本地 Vault 读取和管理。
- 云端工作区和多设备同步。
- 笔记、文件夹、标签、链接和附件管理。
- 知识图谱、孤立笔记、断链和重复内容检查。
- 本地优先，云端同步可选。

### 3.2 普通笔记编辑

- 默认使用视觉化写作，不要求用户理解 Markdown。
- Markdown 作为高级模式保留。
- 标题、列表、引用、代码、图片、表格和任务清单使用工具栏完成。
- AI 编辑以当前笔记为上下文，在编辑页面内通过弹窗完成。
- AI 修改必须支持预览、应用、撤销和版本恢复。

### 3.3 学习与复习

- 自动从笔记生成知识卡片、问题和错题。
- 间隔复习、今日任务和学习进度。
- AI 讲解、举例、反问和模拟考试。
- 将复习记录回写到对应知识点。

### 3.4 AI 工作区

保留网页 AI 和本地 Agent 两种模式：

- 网页 AI：普通用户无需拥有自己的 AI 账号。
- Claude Code：连接用户电脑上的本地 Claude Code。
- Codex：连接用户电脑上的本地 Codex。
- 项目管理：每个项目拥有独立目录、说明和上下文。
- 会话管理：保留历史会话、会话 ID、继续对话和归档。
- Skill 管理：项目级启用、停用和排序。

AI 对话不应只存在于一个全局聊天页面，而应出现在每个功能页面的上下文弹窗中：

- 笔记页面：编辑、总结、改写、提炼知识点。
- 学习页面：讲题、出题、复习和错题分析。
- 图谱页面：解释节点关系和发现知识缺口。
- 整理页面：生成整理建议并预览修改。

## 4. UI 与视觉自定义方向

目标风格：简洁、克制、温暖、具有产品辨识度，同时参考苹果官网的留白、层级、动效和细节质量。

### 用户可以自定义

- 浅色、深色和自动主题。
- 主色、强调色和状态色。
- 背景图片、渐变、纹理或纯色。
- 首页卡片显示和排序。
- 侧边栏、底部栏和页面布局。
- 字体、字号、行高和阅读宽度。
- 卡片圆角、阴影和密度。
- 专注页面的背景、环境音和视觉效果。
- 首页工作区、学习工作区和写作工作区的独立布局。

### 视觉组件体系

- 统一按钮、卡片、弹窗、标签和通知组件。
- 所有页面支持响应式布局。
- 手机端优先考虑单手操作、底部导航和抽屉式面板。
- 动效服务于状态反馈，不追求无意义的复杂动画。
- 提供“默认漂亮配置”，用户不需要配置也能获得完整体验。

### 自定义保存方式

主题和布局应保存为可导出的配置：

```text
用户账号
 └── 工作区
      ├── theme
      ├── layout
      ├── dashboard
      ├── aiStyle
      └── enabledSkills
```

后续可以支持主题模板、社区分享和一键导入。

## 5. AI 语气与人格风格

AI 不应只有一个固定语气。用户可以选择或自定义：

- 温和陪伴。
- 简洁直接。
- 教师讲解。
- 考研辅导。
- 苏格拉底式提问。
- 严格批改。
- 专业研究。
- 内容创作。

用户可以调整：

- 回复长度。
- 是否主动提问。
- 是否给出步骤。
- 是否使用表格。
- 是否先给结论。
- 是否指出错误。
- 是否引用知识库原文。
- 是否在回答末尾生成下一步行动。

项目级 AI 配置优先于全局配置，功能页面可以提供推荐风格：

```text
全局风格
  ↓
项目风格
  ↓
页面任务风格
  ↓
本次对话临时要求
```

## 6. 登录、手机端与云端知识库

### 账号模式

- 游客模式：本地功能可以直接使用。
- 登录模式：启用云端同步、手机端访问、AI 额度和多设备管理。
- 工作区：一个用户可以拥有个人工作区和多个项目工作区。
- 设备：记录桌面端、手机端和本地 Agent Connector。

### 数据模式

#### 本地优先模式

- 知识库保存在用户电脑。
- 不强制上传全部内容。
- 适合本地 Agent 和隐私敏感用户。

#### 云端同步模式

- 笔记、设置、AI 会话和学习记录跨设备同步。
- 附件放在对象存储。
- 支持版本、冲突副本和回收站。

#### 私密模式

- 用户内容加密后上传。
- 平台 AI 默认不能读取私密内容。
- 可以使用本地 Agent 或用户自己的 AI。

## 7. 平台 AI 服务

用户没有 AI 账号时，由 Knowledge Viz 提供平台 AI：

- 服务端统一管理模型和 API 密钥。
- 移动端和网页端只访问自己的 AI 网关。
- 按用户、工作区和套餐记录用量。
- 免费用户提供有限额度。
- 会员用户提供固定额度。
- 高消耗用户支持额外购买额度。
- 高级用户可以使用自己的 OpenAI-compatible API。
- 本地 Agent 用户可以连接自己的 Claude Code 或 Codex。

平台 AI 请求链路：

```text
用户登录
  ↓
权限检查
  ↓
额度检查
  ↓
读取用户授权的知识
  ↓
模型路由
  ↓
返回结果并记录用量
```

API Key、用户凭据和本地 Agent 凭据不得发送到浏览器或手机端。

## 8. 用户管理与运营后台

后台第一阶段需要支持：

- 用户列表和注册时间。
- 最近活跃时间。
- 客户端版本。
- 设备数量。
- 工作区数量。
- AI 使用量和剩余额度。
- 会员状态。
- 功能灰度分组。
- 用户反馈和错误记录。
- 禁用账号、重置额度和注销账号。

默认只统计用量和错误，不读取用户笔记正文。用户内容分析必须提供明确开关。

## 9. 商业化方向

### 免费版

- 本地知识库。
- 基础笔记和学习功能。
- 每日少量平台 AI。
- 单设备或有限云同步。

### Pro 版

- 多设备同步。
- 更高 AI 额度。
- AI 项目、会话和 Skill。
- 高级主题和布局。
- 更多附件和历史版本。

### 高级版

- 更强模型。
- 更大 AI 额度。
- 团队或家庭工作区。
- 分享页面和公开知识卡片。
- 高级 Agent Connector。

## 10. 实施路线

### 阶段一：降低上手门槛

- 视觉化写作作为默认编辑模式。
- 功能页面 AI 弹窗。
- 新手引导和示例数据。
- 默认漂亮主题。
- 基础主题、布局和 AI 语气设置。

### 阶段二：完善桌面端 AI

- 项目、会话和 Skill 工作区。
- 本地 Claude Code/Codex Connector。
- Agent 连接状态、权限提示和错误恢复。
- AI 编辑预览、应用、撤销和版本记录。

### 阶段三：账号与手机端

- 登录和设备管理。
- 云端工作区。
- 笔记和设置同步。
- 手机端查看、编辑、复习和 AI 查询。
- 平台 AI 网关和额度系统。

### 阶段四：商业化与生态

- 会员套餐和额度购买。
- 主题模板和 Skill 分享。
- 分享页面和公开知识卡片。
- 用户反馈、灰度发布和数据分析。

## 11. 产品决策原则

1. 默认简单，复杂功能逐层展开。
2. 默认视觉化写作，Markdown 保留为高级能力。
3. 本地优先，但不阻碍手机端和云端同步。
4. 平台提供 AI，同时支持用户自己的 AI。
5. 用户数据归用户，后台只收集必要的运营数据。
6. 每一个 AI 修改都应该可预览、可撤销、可恢复。
7. 自定义应该服务于效率和表达，而不是增加配置负担。
8. 先把核心链路做稳定，再扩展社区、分享和商业化。
